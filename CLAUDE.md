## Что это и зачем

Qt5/C++17-переписывание старого MFC-приложения Digit (DAPPSIM) для обработки
интерферограмм: изображение → полосы → фаза → волновой фронт → полиномиальный
анализ (базис Серегина / Цернике) → отчёт.

Конечная цель (восстановлена из переписки, Илья её принял): не просто порт, а
программа для **стенда с ИК-интерферометром** (10,6 мкм, схема Тваймана–Грина,
контроль *шлифованных* поверхностей) при шлифовально-полировальном станке.
Карта отклонений должна уходить в **CAM** для правки детали. Отсюда важность
знака карты, коррекции дисторсии и работы при вибрациях.

Люди:

  стенд. Считает главным для цеха: БПФ + апертуры + коррекция дисторсии по
  реперам (`notes/addition-info.txt`); хочет в отчёте PSD, КЭ, градиенты,

## Окружение и сборка

- Должно работать на **Windows 7**: Qt **5.15** (не Qt6), MSYS2 **MINGW64**
  (не UCRT64), `_WIN32_WINNT=0x0601`.
- Сборка из MSYS2 (пути — машины Ильи, на другом ПК сверь):
  ```
  C:/msys64/usr/bin/bash.exe -lc "cd '/c/Ilya/dev/cpp/qt/digit-qt' && cmake --build build -j 1"
  C:/msys64/usr/bin/bash.exe -lc "cd '/c/Ilya/dev/cpp/qt/digit-qt/build' && PATH=/mingw64/bin:\$PATH ctest --output-on-failure"
  ```
  Опции CMake: `DIGITQT_BUILD_TESTS=ON`, `DIGITQT_BUILD_TOOLS=ON` (terminal_pipeline,
  mtr_diff), `DIGITQT_BUILD_PLUGIN_POC=ON` (selftest-утилиты плагинов).
- На основной машине ~7 ГБ ОЗУ: `cc1plus` на файлах с Eigen падает с
  «out of memory» — это нехватка памяти, а не ошибка кода. Собирать с `-j 1`/`-j 2`.
- Если открыт `DigitQt.exe`, линковка падает с «Permission denied» — попроси
  закрыть программу.
- Диагностика clangd в IDE часто отстаёт от правок; истина — компилятор.
- `test_data/report.txt` и `Terminal.pol` — в **Windows-1251**.

## Устройство кода

- `src/core/` — Qt-свободная библиотека `DigitQt::Core`: модель (`Measurement` —
  единственный «документ», `Bitmap`, `PhaseMap`), этапы конвейера
  (`pipeline/stages/`: Setup = загрузка+апертура+трассировка, S2 фаза, S4 фронт,
  S5 полиномы). Qt-свобода гарантирована тем, что Qt к цели не линкуется.
  Исключение — `core/commands/` (QUndoCommand), собирается прямо в приложение.
- `src/aperture/` — геометрия и маски, Qt-свободная.
- `src/formats/` — Qt-свободные адаптеры импорта (`IFormatAdapter`: probe по
  содержимому + `ImportedData` с отчётом о потерях). Есть `.mtr`, `.frn` (два
  диалекта: Digit и WinFringe). Экспорт пока в старом Qt-слое `src/io/`.
- `src/gui/` — MainWindow, ParametersDock, канвас и виды.
- `plugin-sdk/` — C ABI плагинов. **Все 4 трассировщика и 3 метода фазы
  (сплайн, Фурье, вейвлет) существуют только как плагины-DLL**, встроенных
  копий в core нет намеренно. **Исключение — PSI**: встроен в core
  (`src/core/psi/`), потому что ABI фазы принимает одно изображение, а не серию.
- Модель работает на изображении **с полем** (`padImageBackground`, 15% с каждой
  стороны) — учитывать при импорте/экспорте координат.

## Как работать с Ильёй

Он явно называет режим — не угадывай:
- **«пиши код в чат»** — только предложение текстом, файлы не трогать
  (для фундаментальных решений).
- **«напиши всё сам» / «продолжи»** — правишь, собираешь, гоняешь тесты, отчёт.
- **«обучающий разбор»** — сначала общий принцип, потом пример; каждую развилку
  выносить на его решение; первый экземпляр пишешь сам, параллельный отдаёшь
  ему и проверяешь, а не исправляешь молча. Он параллельно ведёт конспект в
  Obsidian.

Правила, которые сложились:
- Перед развилками с последствиями — короткий вопрос с рекомендацией.
- Проверка после изменений в core: полная пересборка + `ctest`; при изменениях
  обработки пикселей — ещё `terminal_pipeline` на `test_data/Terminal.bmp` и
  `mtr_diff` против эталона старого Digit `Terminal_digit.mtr`.
- Коммиты по просьбе, на ветке (не в `main`), сообщения по-русски в стиле
  `feat: …` с подробным телом и разделом «Верификация».
- Чужие файлы (`.clangd`, `.vscode/settings.json`, PDF в `notes/`) в коммиты
  не включать без его слова.
- Исходники старого Digit — `C:\Ilya\dev\cpp\DAPPSIM` (только на основной

Проверенные числа (RMS остатка S5, λ, без двойного хода): E с номинальными 90° —
0,02975 (статья 0,02978), с найденными сдвигами — 0,00036 (статья 0,00031).

Открытые вопросы и известные недоработки:
- **Знак карты.** (φ, δ) и (−φ, −δ) дают одинаковые кадры; выбирается решение,
  чьи сдвиги ближе к номинальным. На примере рис. 8 (0/10/110/30) это даёт
  перевёрнутую карту без предупреждения. Письмо Серегину с 6 вопросами
  (соглашение о знаке, гарантия знака при вибрациях, реальные серии кадров,
  модель «случайного наклона», рабочие параметры) подготовлено, ответа нет.
- Рис. 8 с номинальными 90°: у нас RMS 0,241 λ против 0,0485 в статье —
  вероятно, ошибки развёртки на целые порядки; не разобрано.
- S5 «RMS before» считается без вычитания среднего (`Σz²`) и зависит от
  произвольной константы карты.
- Экспорт `.frn` пишет координаты и размер изображения с полем, но имя
  исходного файла — несовместимо с Digit/WinFringe.
- В UI нельзя посчитать PSI без уточнения сдвигов (для сравнения со статьёй).

Возможные следующие шаги (решает Илья): галочка «уточнять сдвиги» на S2;
сдвиг со случайным наклоном; кадры глубже 8 бит; PSI как плагин (нужна новая
версия ABI для серии кадров); экспорт через адаптеры; коррекция дисторсии по
реперам (G1/G2 из `notes/architecture.md`); список анализов для отчёта (ждёт
таблицу Чекаля).
