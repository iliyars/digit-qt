# Автоапертура PSI, 3 ноября 2026

Сообщение пользователя: после открытия нескольких кадров автоопределение
оставляет счётчик `1 border`, но граница не видна на холсте.

## Найденные проблемы и изменение

Контроллер применял однокадровое определение по пространственной дисперсии
только к первому кадру, даже при наличии PSI-серии. Это не использует
временную модуляцию и может выбрать фрагмент зрачка, если на первом кадре
нет полос либо их мало. На сохранённых сериях получены смещённые эллипсы:
например, `test_shift-PHASE`, полуоси примерно 351/477 вместо 511/511.

Старая подгонка через `Ellipse::FitEllipse` проверялась только на nullptr,
хотя функция всегда создаёт объект. Геометрия результата не проверялась.
Таким образом, наличие объекта в счётчике само по себе не гарантировало
конечный, ненулевой контур. Точный набор кадров из текущего запуска пользователя
не указан; воспроизведение и проверка выполнены на локальных сериях и синтетике.

Теперь при наличии серии используется размах яркости каждого пикселя по всем
кадрам. Порог `max(6, 0,1 * percentile99(span))` рассчитан для текущих 8-битных
данных; процентиль ограничивает влияние одиночных горячих пикселей. Открытие
и закрытие маски ядром 3×3 удаляют мелкие выбросы. По самому большому внешнему
контуру строится эллипс. Его центр, оси и угол проверяются на конечность,
ненулевой размер и разумный масштаб до замены существующей границы.

Обычное изображение продолжает использовать пространственную дисперсию.
Оба режима используют `cv::fitEllipse` с явной проверкой геометрии вместо
непроверенного объекта прежнего fitter. Координаты серии сохраняются вместе
с техническим полем; дополнительного сдвига или масштабирования нет.
Удаление старой внешней границы и добавление новой остаются одной Undo-командой.

## Проверка

Новый набор `AutoApertureDetectionTest` проверяет:

- PSI с первым кадром без пространственного контраста: границу видно только по серии;
- смещённую эллиптическую апертуру и правильный перенос с полем;
- тусклый край пучка, чтобы не принять перепад освещения за край зрачка;
- отказ на плоской серии, горячем пикселе и несовпадающих размерах;
- однокадровое изображение с полосами;
- путь контроллера, сигнал обновления, Undo/Redo;
- настоящий `BoundaryItem`: непустой контур и зелёные пиксели после
  растеризации через QGraphicsScene, а не только счётчик объектов.

Диагностический прогон с тем же полем, что GUI:

| Серия | Центр в исходных пикселях | Полуоси, пиксели |
| --- | --- | --- |
| `test_shift-PHASE` | (512,02; 511,00) | 511,03 / 511,08 |
| `demo_everything` | (127,50; 127,50) | 114,75 / 114,75 |
| `everything_beam` из notebook | (127,50; 127,50) | 114,75 / 114,75 |
| локальная `big.idf` | (129,61; 117,75) | 106,86 / 107,36 |

Для `big.idf` это только геометрическая диагностика: серия не является
эталоном точности. Автоапертура остаётся редактируемым начальным приближением.
Изменение яркости фона между экспозициями, движение, слабые/близкие сдвиги,
сильный шум, неэллиптический или обрезанный зрачок могут нарушать предположения.
Пустая временная модуляция не заменяется молча однокадровой границей.

Полные сборки Debug и Release успешны. CTest: 14/14, 62,10 с.
Трассировка `Terminal.bmp` сохранила 41 линию/2512 точек; RMS разности
с `Terminal_digit.mtr` 13,49/9,47 нм до/после удаления мод, без изменения.
Подготовлен `DigitQt-win7-2026-11-03-auto-aperture-windows-x64.zip`.
# Дополнение: одиночный кадр с неравномерными полосами

Воспроизведён ошибочный выбор части круглого зрачка на синтетическом кадре
с чёрным фоном и изогнутыми полосами переменной частоты (256 и 825 пикселей).
Глобальный порог Otsu по локальной дисперсии отбрасывал области редких полос.
Порог ограничен сверху; после замыкания маски компенсируется расширение
границы окном локальной статистики. Детектор PSI по временному размаху
не изменён. Добавлен регрессионный тест центра и размеров зрачка.

Исходный файл пользовательского скриншота не предоставлен: проверка выполнена
на синтетическом воспроизведении, а не на точном исходном изображении.
