# PSI: наклоны при неоднородном освещении

Проверка по сообщению пользователя: в `psi_demo.ipynb`, сценарий
`everything_beam`, заданные наклоны расходятся с восстановленными.
Notebook не изменялся: его локальные параметры и результаты принадлежат пользователю.

## Причина и сравнение до исправления

На одинаковых кадрах отдельный диагностический исполняемый файл со старыми
`PhaseShifting.cpp/.h` из `7ebe0b8` и текущая реализация до этого исправления
дали одинаковые значения (до 12 значащих цифр), 50 итераций и невязку 2,0908601.
Debug/OpenCV 5 и Release/статический OpenCV 4.13 также совпали.
Следовательно, на воспроизведённом случае расхождение не вызвано QR/SVD или
последней упаковкой. Это ограничение исходного пространственного шага Liu:
предположение об однородных фоне и амплитуде не выполняется при `beam=True`.
Предыдущее расширение фотометрии касалось только общих сдвигов без наклонов.

Параметры взяты из `PRESETS['everything_beam']`: 5 кадров 256×256,
сдвиги 0/80/175/290/20°, наклоны X 0/0,3/−0,4/0,2/0,5,
Y 0/−0,2/0,3/0,4/−0,3 волны на кадр. Все аберрации пресета,
гауссов пучок, шум σ=1, seed=1. Истина не менялась для подгонки результата.

## Исправление

После выбора старта и итераций Liu выполняется variable projection для модели
`I_np = a_p + c_p*cos(δ_np) − s_p*sin(δ_np)`, где сдвиг каждого кадра — плоскость.
Для каждой точки SVD исключает три фотометрических коэффициента; совместно
уточняются центральный сдвиг и два наклона всех кадров, кроме первого.
Координаты нормированы на ширину/высоту кадра, поэтому все параметры имеют
одинаковые угловые единицы. Проецированные градиент и матрица GN включают
производные по всем трём параметрам каждой плоскости.

Требуются ≥5 кадров, достаточный ранг проецированной системы и оставшийся
бюджет итераций. При недоступности уточнения сохраняется результат Liu.
Каждый принятый шаг уменьшает сумму квадратов на неизменном наборе точек;
неудачный временной fit не позволяет незаметно исключить точку из цели.
Демпфирование и ограничение шага предотвращают большой скачок ветви.
Флаг `illuminationRefined` и интерфейс/экспорт/CLI теперь отражают уточнение
также для модели с наклонами. `psi_demo.run_demo` печатает путь к использованному
`psi_check`, чтобы автоматический выбор свежей сборки был виден.

## Результат на точных кадрах notebook

| Показатель | До | После |
| --- | ---: | ---: |
| Максимальная ошибка центральных сдвигов | 3,109° | 0,011° |
| Максимальная ошибка наклонов X/Y, волн на кадр | 0,07308 | 0,000182 |
| Невязка яркости | 2,09086 | 0,65968 |
| RMS ошибки развёрнутой карты, периодов | 0,01608 | 0,00250 |
| Максимальная ошибка коэффициентов S5, волн | 0,02175 | 0,00010 |

В таблице ошибок карты удалена только постоянная фаза. Нулевой вывод
`tilt_err=0.0000` в демо означает округление печатаемых наклонов, а не отсутствие
ошибки: точное сравнение сделано отдельным диагностическим solver probe.
Сохранён [полный отчёт до/после](audit/psi-tilt-beam-before-after.json).

Новый C++ тест воспроизводит смешанные аберрации, независимые X/Y наклоны,
пучок и шум. Генератор шума в C++ другой, поэтому тест проверяет допуски
(0,1° сдвиги, 0,002 волны наклоны, RMS фазы <0,02 рад), а не совпадение кадров
с NumPy. Он проходит вместе с остальными 42 проверками PSI.

Изменение не исправляет освещение, меняющееся между экспозициями, насыщение,
движение XY, неоднозначность знака и ошибки развёртки. Оценка условного шума
для модели с наклонами по-прежнему недоступна. Пространственная диагностика
расхождения половин для наклонов всё ещё использует исходную модель;
её показания при пучке требуют осторожной интерпретации.

Полная сборка Debug и Release успешна. CTest: 13/13, 56,54 с. Регрессия
`Terminal.bmp` сохранила 41 линию/2512 точек и RMS разности с эталоном
13,49/9,47 нм до/после удаления мод. После пересборки Release точные кадры
`everything_beam` дают одинаковые отчёты и карты в Debug и Release.
Архив Windows x64 обновлён; проверка его зависимостей и запуск на машине
разработки не заменяют испытание на Windows 7.
