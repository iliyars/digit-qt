# Конспект по алгоритмам DigitQt (для переписывания в блокнот)

Короткая версия учебника `uchebnik-interferometriya-i-digitqt.md`: только суть,
формулы и «зачем». Каждый раздел — примерно одна страница блокнота.
Сверено с кодом на 2026-09-21.

---

## 0. Одна картинка: весь конвейер

```
снимок ──► апертура ──► S1 трассировка ──► S2 фаза ──► S4 волн. фронт ──► S5 полиномы
 (BMP)    (маска)      (линии + номера)   (карта N)      (нм)            (коэффициенты
                                                                          + остаток)
```

Что течёт между стадиями:

| Стадия | Выход | Единицы |
|---|---|---|
| S1 | линии полос: список точек + номер `order` | пиксели / номер полосы N |
| S2 | `PhaseMap` — карта на всём кадре, NaN там, где данных нет | порядок полосы N |
| S4 | `wavefrontMap` | нм |
| S5 | коэффициенты + `residual` | нм |

Правило проекта: ничего не пересчитывается само. Правка выше по конвейеру
помечает всё ниже как `Stale`, пользователь жмёт Compute сам.

S3 (развёртывание фазы) отдельной стадии нет: у методов по линиям номера полос
уже целые и идут подряд, а у Фурье и вейвлета unwrap спрятан внутри S2.

## 1. Физика в пяти строках

```
I = I0 · (1 + V·cos φ),     φ = 2π · OPD / λ
```

- Полоса — линия равной разности хода (OPD). Соседние светлые полосы отличаются на λ.
- Номер полосы N = OPD / λ. Это главная величина проекта.
- Отражение (double pass): высота h = N·λ/2. Просвет: W = N·λ.
  Переключатель `isDoublePass`, по умолчанию `true`.
- Несущая: зеркало намеренно наклоняют, `OPD = аберрация + a·x + b·y`.
  Получается частая решётка почти прямых полос, а форма поверхности видна как
  их искривление. Фурье и вейвлет без несущей не работают.
- λ по умолчанию 632.8 нм (He-Ne лазер).

## 2. Апертура (маска «где вообще есть данные»)

Предикат `isVisible(x,y)`, по шагам:

1. Внутри любой INTERNAL-фигуры → невидимо (обструкция, вторичное зеркало).
2. Надо быть внутри всех EXTERNAL-фигур (пересечение). Если их нет — невидимо.
3. Если после шага 2 невидимо, но точка попала в любую APERTURE-фигуру
   (объединение) — видимо, если её не заблокировал шаг 1.

Формы: эллипс, прямоугольник, полигон.

### 2.1 Автоопределение апертуры (`AutoApertureDetection.cpp`)

Идея: там, где есть полосы, яркость сильно меняется. Фон плоский.

```
Гаусс 5×5  →  локальная дисперсия  var = E[I²] − E[I]²   (окно 15×15)
→ нормировка в 0..255 → порог Оцу → морфологическое закрытие (эллипс 31×31)
→ внешние контуры → самый большой по площади
→ МНК-подгонка эллипса (не более 200 точек контура)
```

- Дисперсия, а не яркость: не важно, светлый фон или тёмный.
- Закрытие 31×31 склеивает тёмные полосы, которые тоже локально «плоские».
- Подгонка идёт в координатах относительно центроида, иначе система 5×5
  плохо обусловлена; потом результат сдвигается обратно.

### 2.2 Паддинг фона

Вокруг кадра добавляется рамка (15% большей стороны) цвета фона. Цвет фона —
мода пикселей по периметру. Зачем: чтобы апертура не упиралась в край кадра.

## 3. S1: трассировка полос — найти центр каждой полосы

Результат: `TracedLine` — цепочка точек `(x, y, width, intensity)`.

| Метод | Нужны затравки | Точность | Суть |
|---|---|---|---|
| Sequential (FTM) | да, по одной на полосу | целые пиксели | идти по гребню шагами, ощупывая склон |
| Structure Tensor | да | субпиксель | направление из тензора градиента |
| Scanline Extremum | нет | субпиксель | пики в каждой строке, потом сшивка по строкам |
| Binary Thinning | нет | целые пиксели | бинаризация + скелет Zhang–Suen |

### 3.1 Sequential
Локальная ось «поперёк полосы» квантуется по 45° (4 направления). Ширина полосы —
сколько пикселей яркость выше фона. Шаг: измерить ширину и ось → предсказать
следующую точку вдоль сглаженного направления → подцентрировать поперёк.
Остановка: потеряли полосу (яркость ниже EMA фона), прыжок центрирования слишком
большой (перескок на соседнюю полосу), вышли за апертуру, контур замкнулся.
Идёт вперёд и назад от затравки, два куска сшиваются.

### 3.2 Structure Tensor
В окне вокруг точки считаются градиенты `gx, gy`.

```
S = [ Σgx²    Σgx·gy ]        направление вдоль полосы =
    [ Σgx·gy  Σgy²   ]        собственный вектор МЕНЬШЕГО собственного числа
```

Почему: градиент направлен поперёк полосы, вдоль неё яркость почти не меняется.
Ширина — по полувысоте (FWHM-подобно). Максимум ищется перебором в окне, потом
доводится параболой по x и по y отдельно (3 точки) — это и даёт субпиксель.

### 3.3 Scanline Extremum
Два этапа.

**(а) Пики в строке.** Вычитается фон (для длинных строк > 70 px: 5 частей,
кусочно-линейный фон; для коротких: константа). В каждом непрерывном пробеге
длиной ≥ 5 строится парабола `y = c0 + c1·x + c2·x²` по МНК, пик в вершине:
`x = −c1 / (2·c2) + 0.5`. Режимы: `Max` (светлые), `Min` (тёмные, тот же поиск
на `255−I`), `MinMax` (оба — вдвое больше отсчётов фазы).

**(б) Сшивка (`FringeConstructor`).**
1. Медианный шаг между пиками по всем строкам.
2. «Главная» строка: больше всего пиков при шаге в допуске от медианы. Её пики
   получают номера `0, 1, 2, …` слева направо, каждый — свой `chainId`.
3. Распространение вверх и вниз: точка ищет пару в уже пронумерованных строках —
   тот же тип, |Δx| ≤ допуск, не пересекает уже построенные отрезки, в `MinMax`
   не ломает чередование Red/Black. Не нашла пару: либо новая полоса у края,
   либо «орфан», выбрасывается.
4. Группировка по `chainId`, а не по номеру: иначе две несвязанные части одной
   полосы (до и после обструкции) слипались бы.

Итог: линии уже с осмысленными номерами. Этот метод — единственный, чей номер
берётся из трассировки, а не из эвристики «слева направо» (см. §4).

### 3.4 Binary Thinning
Гаусс → адаптивный порог (локальное среднее − C) → маска апертуры → открытие и
закрытие → скелет Zhang–Suen → обрезка коротких шпор → обход в полилинии →
сшивка разрывов (концы почти коллинеарны, cos > 0.5, и мостик ≥ 60% по маске,
кривая Безье) → фильтр по кривизне.

Zhang–Suen: пиксель снимается, если соседей B ∈ [2,6], число переходов 0→1
вокруг равно 1 и выполнены два условия на соседей (разные в двух подпроходах).
Повторять до стабилизации.

## 4. Нумерация полос

`autoAssignFringeOrder` (`FringeOrdering.cpp`): линии сортируются по среднему X
всех точек, номера `0, 1, 2, …`. Ручные номера (`orderIsManual`) не трогаются, но
счётчик всё равно идёт вперёд.

Абсолютный номер известен только с точностью до общей константы (нужна реперная
точка), поэтому на итоговую форму это не влияет — влияет лишь на пистон.

Автозатравки (`AutoSeedPlacement`): берётся строка с максимумом видимых пикселей,
на ней применяются те же `removeBackground` + `detectPeaks`, что в §3.3.

## 5. Продление полос (новое, `FringeEdgeExtrapolation.cpp`)

Зачем: S2 строит сплайн по строке, ему нужны пересечения с обеих сторон. У полюса
апертуры линии не доходят до края, и там строка остаётся пустой. Решение — дорисовать
искусственные продолжения.

- **Вертикально** (`extrapolateFringesVertically`): каждый конец каждой линии
  продлевается фиксированным вектором шага. Шаг считается один раз и берётся из
  внутреннего сегмента `points[1]−points[2]`, а не из крайнего: крайняя точка
  трассировщика лежит ровно на границе апертуры, и последний сегмент может быть
  случайно коротким. Продление идёт, пока точки не выйдут за апертуру, и
  специально дальше на `overshootMargin` точек — чтобы сегмент пересёк строку.
- **Горизонтально** (`extrapolateFringesHorizontally`): за самой левой и самой
  правой линией добавляется ровно по одной новой линии — параллельный сдвиг
  крайней линии на шаг до её соседа.
- Идемпотентность: если конец уже вне апертуры, повторный вызов ничего не делает.
- Синтетические точки считаются счётчиками `syntheticFront/BackCount`, поэтому
  `removeFringeExtensions` умеет откатить всё обратно. Полностью синтетическая
  линия удаляется целиком.
- После каждой операции заново вызывается `autoAssignFringeOrder`.

## 6. S2: карта фазы. Три метода

### 6.1 Horizontal Spline (по линиям)

Для каждой строки `y` независимо:

1. Найти пересечения всех линий с горизонталью `y`. Сегмент учитывается по
   полуоткрытому правилу `[ymin, ymax)`, чтобы вершина не считалась дважды.
   Горизонтальный сегмент даёт середину.
2. Отсортировать по x и получить пары `(x, номер)`.
3. Схлопнуть пары ближе 1 px в одну (среднее x и номер). Недавний фикс: если
   две линии пересеклись, шаг `h≈0` в методе Томаса даёт всплеск в бесконечность.
4. Натуральный кубический сплайн (метод Томаса, `c₀ = cₙ = 0`).
   Меньше 2 пересечений → вся строка NaN.
5. Вне крайних узлов экстраполяция линейная (касательная), не кубическая,
   иначе на краю получаются загибы.
6. Дозаполнение полюса: NaN-пиксели (видимые) тянутся по вертикали линейной
   интерполяцией между ближайшими решёнными строками столбца.

Почему не Лаплас `∇²z = 0`: гармонично только `ax+by`. Дефокус `ρ²` даёт
`∇²=4`, сферическая `ρ⁴` даёт `16ρ²`. Лаплас вытеснял реальную кривизну к краю.
Сплайн же использует измеренное расстояние между полосами как наклон `dz/dx`.

Сетка решения ограничена 5000 px по длинной стороне (`kMaxGridDimension`).
Слабое место: метод рассчитан на почти вертикальные полосы.

### 6.2 Фурье (Такеда)

```
I = a + b·cos(2π f0 x + φ)  →  спектр: центр + два боковых пика ±f0, оба несут φ
```

1. Вычесть среднее, умножить на окно: приподнятый косинус от края апертуры вглубь
   на 40 px (без него резкий край забивает боковой пик «крестом»).
2. 2D БПФ + fftShift.
3. Найти максимум `|F|` вне круга радиуса 8 вокруг центра. Только в правой
   полуплоскости (`x > cx0`): пики симметричны, и без этого случайно брался
   сопряжённый, что переворачивало знак нечётных членов (наклон, кома, трефойл).
4. Гауссов фильтр вокруг пика, радиус `0.6 · расстояние до центра`.
5. Сдвинуть пик в центр (это и есть вычитание несущей), обратное БПФ.
6. `φ_wrapped = atan2(Im, Re)`.
7. Unwrap: BFS от центра масс апертуры, у каждого нового пикселя
   `wv − round((wv − base)/2π)·2π`, где `base` — значение соседа, из которого пришли.
8. Вернуть потерянный наклон: `carrierPhase = 2π·(fx·(x−cx) + fy·(y−cy))`,
   где `fx = (peakX − cx0)/W`. Итог делится на 2π → номер полосы.

Ограничения: нужна одна чёткая несущая на весь кадр; без полос ошибка
«Could not find a clear carrier frequency».

### 6.3 Вейвлет (Zhong & Weng)

Локально ищет частоту вместо одной глобальной.

```
ψ(t) = exp(i·ω0·t)·exp(−t²/2),  ω0 = 5.5
W(a,x) = (1/√a) · Σ s(τ) · ψ*((τ−x)/a)
```

1. Грубый период несущей из одного глобального БПФ (нужен лишь для диапазона).
2. 16 масштабов на логарифмической сетке от `0.5·период` до `2·период`,
   `a = ω0·период / 2π`. Ядро обрезано на 3σ, но не длиннее 120 px.
3. В каждой видимой точке строки берётся масштаб с максимумом `|W|` (гребень CWT),
   фаза = `atan2(Im, Re)`. Вейвлет одномерный, вдоль строки.
4. Unwrap тем же BFS. В комментарии в коде сказано «сравнение со всеми четырьмя
   соседями», но по факту каждый пиксель сравнивается с тем соседом, из которого
   BFS пришёл. Это расхождение слов и кода, на результат почти не влияет.
5. Деление на 2π. Наклон восстанавливать не нужно: фильтр не вычитает несущую,
   она остаётся в фазе.

Дороже Фурье: в каждой точке свёртка с 16 ядрами. Для Фурье и вейвлета трассировка не запускается
(`SetupStage` очищает линии).

## 8. S5: разложение по полиномам

Цель: отделить «как установили образец» (наклон, дефокус) от реальной формы
(астигматизм, кома, сферическая) и остатка (полировка).

**Нормировка.** Центр и радиус берутся из bounding-box непустых пикселей карты:
`nx = (x−cx)/r`, `ny = (y−cy)/r`, `r = max(ширина, высота)/2`. Края эродируются на
`edgeErosionPixels = 2`: если у пикселя в окне 5×5 нет данных, он в подгонку не идёт.

**Базис Seregin** (как в DAPPSIM, `y` перевёрнут — Y вверх):
```
piston 1 | tiltX x | tiltY −y | defocus x²+y² | astigX 1.5(x²−y²) | astigY −xy
comaX x³+xy²−⅔x | comaY ⅔y−y³−x²y | trefoilX 3xy²−x³ | trefoilY 3x²y−y³ | spher (x²+y²)²
```
**Базис Zernike** — классический, без переворота Y, поэтому знаки Y-термов
обратные. Перевод: `defocus_ser = 2·defocus_z − 6·spher_z`, `spher_ser = 6·spher_z`,
`coma_ser = 3·coma_z`, `astigX_ser = ⅔·astigX_z`, `astigY_ser = −2·astigY_z`.

Три способа подгонки (`ModalFitMethod`):

1. **JointLeastSquares** — один МНК по выбранным термам сразу, `colPivHouseholderQr`.
   Термы не ортогональны, коэффициенты зависят от набора галочек.
2. **GramSchmidtOnAperture** — ортогонализация по реальным точкам апертуры в порядке
   `piston → tilt → … → spherical`. Галочки друг на друга не влияют, но коэффициенты
   не совпадают с другими программами.
3. **SequentialSeregin** — точная копия схемы DAPPSIM, 7 стадий, каждая МНК-ит
   остаток после предыдущих:

```
1. {1, x, −y}                     → piston, tiltX, tiltY
2. {1, ρ²}                        → defocus
3. {1, x, −y, (3x²−1)/2, −xy, (3y²−1)/2} → astig4, astig5, astig6
4. {1, x, −y, comaX, comaY, trefX, trefY} → coma, trefoil
5. {1, ρ², ρ⁴}                    → s3
6. {1, ρ², ρ⁴, ρ⁶}                → s5
7. {1, ρ², ρ⁴, ρ⁶, ρ⁸}            → s7
```
Игнорирует галочки и выбор базиса. Интерсепт стадий 2–7 DAPPSIM отбрасывает,
здесь он копится отдельно (`discardedIntercepts`), иначе остаток не сходится к нулю.
Подтверждено побайтово против `Terminal.pol` только для piston, tiltX, tiltY,
defocus. Остальное — честная транскрипция.

Результат: коэффициенты, `residual = карта − подгонка`, `rmsBefore`, `rmsAfter`.
