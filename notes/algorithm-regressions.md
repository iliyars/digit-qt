# Исправления MinMax и Фурье

Первый этап после алгоритмического аудита, 1 ноября 2026 года.

## Что исправлено

- **Scanline MinMax:** между соседними максимумом и минимумом теперь используется
  половина полного шага порядка. Один и тот же эффективный шаг передаётся в
  обнаружение, построение и перенумерацию полос. Режимы Max и Min сохраняют полный
  шаг. Проверяется вся связка настоящих DLL Scanline → HorizontalSpline.
- **Фурье:** прямой циклический сдвиг спектра и обратный теперь различаются для
  нечётных размеров. Последняя строка/столбец больше не теряются.
- **Кольцевая маска:** если центр масс лежит в экранировании, поиск затравки
  действительно переходит к видимым пикселям.
- **Невычисленные значения:** выход инициализируется NaN; запись разрешена только
  для посещённых пикселей. Несвязная по четырём соседям апертура возвращает отказ
  с объяснением неизвестных относительных порядков. Частичная карта за успешное
  восстановление всей апертуры не выдаётся.
- **Отсутствие сигнала:** добавлены проверки вариации интенсивности внутри маски
  и выделенности спектрального пика. На отказе весь выход остаётся NaN.

Порог интенсивности — RMS не меньше одного отсчёта 8-битной камеры. В поисковой
полуплоскости вне DC-круга мощность максимального бина должна составлять не менее
1% суммарной мощности и превышать среднюю мощность бина минимум в 25 раз.
Это инженерные фильтры неподходящих входов, а не оценка метрологической точности:
они не гарантируют правильную фазу при любом шуме, перекрытии спектров или дефекте.
Широкий спектр полезного сигнала также может привести к отказу.

## Регрессионные испытания

[AlgorithmRegressionTest.cpp](../tests/AlgorithmRegressionTest.cpp) загружает
настоящие плагины приложения через C ABI. Проверяются 19 наборов входных данных:

- Фурье: чётная, нечётная и смешанная чётность размеров, прямоугольный кадр,
  вертикальная, горизонтальная и диагональная несущая, кольцевая апертура.
- Отказы: константа, константа внутри маски при контрастном внешнем фоне,
  детерминированный широкополосный шум, несвязная, пустая и слишком малая маска.
  После каждого отказа тот же экземпляр плагина должен успешно обработать
  корректный кадр и очистить сообщение об ошибке.
- Scanline → сплайн: Max, Min, MinMax для вертикальных и горизонтальных полос.
  Масштаб должен отличаться от 1 менее чем на 0,005; RMS ошибки после удаления
  только пистона — менее 0,01 периода.

Для Фурье отдельно проверяется покрытие всей апертуры, а RMS — в указанной
центральной области радиусом 0,30 размера кадра. Предел RMS — 0,01 периода.
Это разные проверки: покрытие не означает равномерную точность до самого края.
Знак, наклон и масштаб при сравнении с заданной фазой не подгоняются.

## Повтор независимого аудита

На прежних синтетических входах `build/algorithm_audit.py`:

| Случай | До | После |
|---|---:|---:|
| Фурье 129×129, RMS ошибки в периодах | 0,093492 | 0,000774 |
| Фурье 128×128, RMS ошибки в периодах | 0,000787 | 0,000787 |
| Фурье, кольцо, RMS ошибки в периодах | 0,074570 | 0,008037 |
| Scanline MinMax → сплайн, масштаб | 2,000002 | 1,000001 |
| Фурье на константе | Ложный успех | Отказ |
| Фурье на двух отдельных областях | Ложное заполнение | Отказ |

Из RMS исключён только пистон; использована центральная область исходного аудита.
Скрипт аудита и его JSON остаются локальными диагностическими файлами в `build`;
постоянная воспроизводимая защита изменений — CTest выше.

## Запуск

В окружении сборки проекта:

```text
cmake -S . -B build -DDIGITQT_BUILD_TESTS=ON
cmake --build build --target digitqt_algorithm_regression_tests -j 2
ctest --test-dir build -R AlgorithmRegressionTest --output-on-failure
ctest --test-dir build --output-on-failure
```

На Windows каталог `C:/msys64/mingw64/bin` должен находиться в PATH.
Пройден полный набор: 13 из 13 CTest-тестов.

Ограничения Wavelet, глобальной нумерации других трассировщиков и PSI с неизвестными
сдвигами этим этапом не исправляются. Пороговые проверки Фурье не заменяют локальную
оценку качества фазы и проверку на реальных данных стенда.
