# Аудит DigitQt — 2 ноября 2026

Состояние исходников: `main`, `7ebe0b8`. Код приложения в ходе аудита не менялся.
Новые материалы: этот отчёт, [roadmap](ROADMAP.md) и воспроизводимые проверки в
[audit/](audit/). Измерения ниже получены на локальной Debug-сборке Windows x64.

**Вывод:** проект имеет работающий вычислительный каркас, но пока является
исследовательским приложением. До производственного применения нужны исправления
отчёта и Wavelet, явная модель физических величин, контроль качества карты,
калибровка, сохранение измерения и проверенный обмен с CAM. Переписывать всё
заново оснований нет. Отождествлять успешный расчёт с достоверным измерением нельзя.

## 2. Архитектура: фактическая реализация

| Область | Что есть | Что существенно отсутствует |
|---|---|---|
| Core | Qt-свободные данные и алгоритмы; отдельная aperture-библиотека | Типизированные физические карты, Grid/CoordinateFrame, полноценный QC |
| Pipeline | Setup, S2, S4, S5; контроль изменений и устаревания | S4b, S6, S7 — заглушки; история происхождения результатов |
| Плагины | C ABI, opaque handle, память выхода фазы у хоста | Серия кадров в phase ABI, параметры фазы, quality/component maps, progress/cancel |
| Ввод | Изображение, PSI-серия, MTR, два диалекта FRN | Сохранение всего измерения; полноразрядные кадры камеры |
| Геометрия | Маски, реперы, МНК аффинного преобразования | Применение G2 к данным, G1-дисторсия, G3 к детали |
| Анализ | Фаза, карта в нм, низшие полиномы, RMS/PV, оценка Strehl | КПФ, физические градиенты/PSD, производственная приёмка, CAM-контракт |
| GUI | Undo/redo, 2D/3D, русский/английский, фоновые вычисления | Проектный файл, восстановление сессии, прерывание долгих вычислений |
| Доставка | CI сборки/тестов, Release workflow, Win7-ориентированная упаковка | Проверка содержимого релиза и запуска на целевых чистых машинах |

Сильные решения, которые стоит сохранить: единственное Measurement, отделение
алгоритмов от Qt, адаптеры с отчётом потерь, настоящий C ABI, тестирование настоящих
DLL, раздельные исходная и остаточная карты, инвалидация и снимки параметров S4/S5.

`CLAUDE.md` полезен как история, но часть текста устарела: указание работать на
ветке `psi`, старое состояние Фурье и отсутствие предупреждений PSI нельзя
принимать за текущее описание. В GUI предупреждения о несходимости, зеркальном
решении и раздельных областях уже есть. В CMake также остались комментарии о
встроенном fallback, которого код больше не содержит.

## 3. Подтверждённые дефекты

Приоритет P0 означает блокирование производственного использования соответствующего
результата; P1 — исправить до измерительного релиза; P2 — следующий инженерный этап.

### A01 · P0 · Модуль астигматизма Серегина зависит от поворота

Место: `src/core/ModalAnalysisReportData.cpp`, вычисление `astigMagnitude`.
Подгоняемые термы: `1.5*(X²−Y²)` и `XY`, где Y направлен вверх.
Их коэффициенты имеют разный масштаб, поэтому их обычная евклидова норма
не является вращательно-инвариантной амплитудой астигматизма.

Настоящая подгонка карты
`W = 100*[cos(2α)*(X²−Y²) + sin(2α)*2XY] нм` даёт:

| Базис | Поворот 0° | Поворот 45° | RMS остатка |
|---|---:|---:|---:|
| Серегин, модуль в отчёте | 66,6667 нм | 200 нм | < 5e−14 нм |
| Цернике Unit, модуль в отчёте | 100 нм | 100 нм | < 5e−14 нм |

МНК работает, ошибается представление результата. Для амплитуды в виде
`A*(X²−Y²)+B*2XY` нужно `hypot(1.5*astigX, 0.5*astigY)`.
Историческое значение WinFringe, если нужно, следует показывать отдельно
с собственным названием и определением, а не выдавать за физический модуль.
Нужна проверка серии углов и согласованности обоих базисов.

### A02 · P0 · Wavelet выдаёт карту при отсутствии полос

Место: `plugin-sdk/wavelet_phase_plugin/plugin.cpp`, поиск периода и выбор ridge.
На кадре, полностью заполненном 128, возвращается успех, покрытие 100%,
PV в центральной области **2,30991 периода**. Fourier на том же входе
возвращает отказ `Insufficient intensity contrast inside aperture`.

Граница маски создаёт спектральную структуру; одного максимума вне DC
недостаточно для установления наличия несущей. У Wavelet также отсутствует
порог достоверности локального комплексного коэффициента.

### A03 · P0 · Wavelet не поддерживает произвольное направление полос

Оценка периода использует длину двумерного вектора частоты, но сама свёртка
выполняется только вдоль X. Для горизонтальных полос полезная несущая
направлена вдоль Y; физическая модель такого вычисления не соответствует входу.

На синтетике `fy=18`, `fx=0`, 128×128, с небольшой кривизной:
Fourier RMS = **0,000596 периода**, Wavelet RMS = **2,84840 периода**.
Оба возвращают успех. В обоих сравнениях удалён только пистон.

Исправление: либо ориентированный/двумерный вейвлет, либо честное ограничение
поддерживаемого направления с отказом до вычисления. Операция поворота требует
отдельной проверки интерполяционной ошибки и обратного отображения маски.

### A04 · P1 · Wavelet молча возвращает половину апертуры

На двух раздельных кругах успех возвращается с **50% покрытия**.
Обход развёртки посещает одну компоненту, успешность определяется наличием хотя
бы одного пикселя. Fourier на том же входе правильно отказывается, поскольку
относительный целый порядок компонент неизвестен.

Нужен общий контракт компонент и покрытия для всех методов. Частичное решение
допустимо только как явно обозначенное частичное решение с маской результата.

### A05 · P1 · G2 принимает необратимое отображение

Место: `src/core/FiducialTransformFit.cpp`.
Три неколлинеарных исходных репера с одинаковыми целевыми координатами дают
`ok=true`, определитель линейной части 0, RMS 0. Проверяется ранг исходной
матрицы, но не пригодность результата как координатного преобразования.

Нужны конечность коэффициентов, обратимость, обусловленность и явная политика
отражения/масштаба. Это блокер именно для будущего resampling/G2: сейчас
полученное преобразование не применяется к фазе и потому эту карту не портит.

### A06 · P1 · Неизвестные единицы MTR принимаются за волны

Место: `src/formats/MtrAdapter.cpp`, обработка `Units=`.
Для неподдерживаемой единицы значения остаются без перевода и попадают в phaseMap;
пользователь получает уведомление о потере, после чего GUI уже запускает S4/S5.
Числовой результат при этом может иметь неверный физический масштаб.

Для неизвестных единиц нужен отказ либо явный импорт с заданным преобразованием.
Отсутствующие единицы требуют записанного предположения. OPD, поверхность и фаза
не должны определяться текущим состоянием чекбокса, унаследованного от другой работы.

### A07 · P2 · `terminal_pipeline` не находит свои плагины после сборки

Штатный запуск `build/tools/terminal_pipeline/terminal_pipeline.exe` завершился
ошибкой загрузки трассировщика. Плагины скопированы в `build/src/plugins`,
загрузчик ищет их относительно EXE. CMake инструмента не задаёт общий выходной
каталог и не развёртывает DLL рядом с ним.

Контрольная копия того же EXE в `build/src` успешно отработала: **41 линия,
2512 точек**. Нужно исправить размещение/поиск плагинов и зависимости целей,
а не требовать ручного копирования для штатной диагностики.

### A08 · P2 · Активный `big_4.idf` не читается

Его первая строка: `54 Interferograms descriptive file`.
Парсер допускает только точное `Interferograms descriptive file`.
`psi_check` воспроизводимо отказывается ещё до загрузки кадров.

Это расхождение локального примера и принятого формата. Происхождение `54`
не установлено: не следует автоматически объявлять это легальным вариантом
формата. Сначала выяснить, повреждён ли файл; затем либо исправить копию данных,
либо документировать расширение парсера и добавить реальный fixture.
Исходный файл аудитом не изменялся. `notes/IDF/` исключён из Git.

## 4. Алгоритмы: что верно, а где проходит граница применимости

### Fourier

Последовательность «вычитание среднего → аподизация → FFT → боковая полоса →
IFFT → аргумент → развёртка → возврат несущей» соответствует подходу Такеды.
Нечётные размеры, кольцо и отказы на константе/раздельной апертуре уже исправлены
предыдущим этапом; независимый прогон это подтверждает.

| Проверка | RMS в периодах, только без пистона |
|---|---:|
| 128×128, вертикальные полосы | 0,000596 |
| 128×128, горизонтальные полосы | 0,000596 |
| 128×128, диагональные полосы | 0,000600 |
| 129×129 | 0,000613 |
| Кольцевая маска | 0,001644 |

Область оценки RMS — центральный круг радиусом 0,30 размера кадра;
покрытие считается отдельно по всей апертуре. Это не оценка точности края.

Ограничения текущей реализации:

- Выбор положительной полуплоскости задаёт **математическое соглашение**, а не
  устанавливает физический знак высоты. Для отрицательной несущей проба получила
  масштаб −0,999995 относительно исходной фазы. Это не устранимо знанием одного
  `cos(φ)`: необходимо внешнее соглашение/калибровочное воздействие.
- Поиск пика имеет фиксированный DC-радиус 8 бинов, аподизация — 40 px,
  ширина Gaussian — 0,6 расстояния до DC. Эти параметры не универсальны.
- BFS-развёртка не использует локальную достоверность и не контролирует
  несогласованность обхода замкнутых контуров.
- Нет интерактивного выбора боковой полосы/маски спектра и явной оценки
  разделимости спектров. Наличие сильного пика не доказывает правильность фазы.

### Wavelet

На поддерживаемой вертикальной синтетике в центре ошибка мала: **0,000323
периода**. На кольце она выросла до **0,031923**. Нельзя переносить этот успех
на горизонтальные полосы или отсутствие сигнала: дефекты A02–A04 это опровергают.
Нужны адаптация направления, вычитание фона, контроль края окна, качества ridge,
покрытия и развёртки. До этого статус метода — экспериментальный.

### PSI с известными сдвигами

Модель `I_n=a+c*cos(δ_n)−s*sin(δ_n)`, затем `atan2(s,c)` и
`hypot(c,s)/a` алгебраически соответствует формулам (6)–(8) статьи 2012 года.
На независимой 8-битной синтетике известные сдвиги дали RMS **0,000366 периода**
при равномерном освещении и **0,000787** при неоднородном.

Численная слабость: явное обращение нормальной матрицы 3×3 с проверкой
определителя. Для близких сдвигов нужна оценка обусловленности исходной матрицы
и предпочтительно QR/SVD. Малый ненулевой определитель не означает достаточной
точности. Три кадра математически достаточны при известных невырожденных сдвигах,
но почти не дают избыточности для оценки соответствия модели.

### PSI с неизвестными сдвигами и наклонами

Чередование оценки фазы и сдвигов соответствует статье 2012 года. Но шаг оценки
сдвига по всему полю использует один фон/амплитуду для кадра. Статья вводит
предположение постоянной амплитуды; реальная пространственная неоднородность
освещения остаётся существенным ограничением. Отбор по размаху это не устраняет.

| Освещение | Сдвиги известны | Сдвиги уточняются |
|---|---:|---:|
| Равномерное: RMS фазы, периоды | 0,000366 | 0,000366 |
| Неоднородное: RMS фазы, периоды | 0,000787 | 0,001633 |
| Неоднородное: максимальная ошибка сдвига | 0° | **2,81682°** |

Во втором случае итерации сообщили `converged=true`. Это подтверждённая граница
применимости модели, а не доказательство неправильного переноса формул статьи.
Следующий шаг — нормализация/модель неоднородного фона и амплитуды с проверкой
смещения на синтетике; нельзя просто уменьшить порог остановки.

Компенсация наклонов структурно соответствует трём шагам Liu et al. 2013.
В самой статье предполагается постоянство фона/амплитуды внутри строки или
столбца при соответствующей подгонке. Реализация добавляет несколько стартов
по спектру — разумная эвристика, но не гарантия глобальной сходимости.
Нужны стресс-тесты: слабая несущая по одной оси, амплитудные градиенты, speckle,
насыщение, изменение экспозиции, движение XY и вибрация за время экспозиции.
Последняя не сводится к фазовому сдвигу между кадрами.

### Развёртка и знак

`PhaseUnwrapping.cpp` правильно выбирает ближайший соседний порядок по 2π и
обходит области по приоритету качества. Для достоверной фазы нужен достаточно
малый межпиксельный фазовый шаг; разрывы, шумовые residues и независимые
компоненты требуют дополнительных правил. Разные компоненты сейчас получают
независимые начала, затем могут вместе попасть в S5. Предупреждение в GUI есть,
но машинно-читаемого статуса «относительные порядки неизвестны» в карте нет.

Неизвестный PSI допускает `(φ,δ) ↔ (−φ,−δ)`; близость к номинальным сдвигам
не является доказательством знака. Флаг `mirrored` фиксирует совершённый выбор,
а не подтверждает направление. Для карты коррекции нужны проверенный знак,
ориентация XY и привязка к детали.

### Трассировка и сплайн

Исправление половинного шага MinMax в Scanline уже имеется; настоящий
Scanline → HorizontalSpline защищён регрессиями. Это исправление не нужно
включать в roadmap как новую задачу.

Глобальная нумерация остальных трассировщиков слабее: fallback в
`FringeOrdering.cpp` сортирует линии по среднему X и увеличивает порядок на 1.
Он не решает топологическую задачу замкнутых, горизонтальных или разорванных
полос и не различает два фрагмента одного порядка. Это ограничение видно из
кода; все такие случаи отдельными численными испытаниями в этом аудите не покрыты.

Natural cubic spline реализован стандартно; линейное продолжение за крайними
узлами сделано явно. Но сплайн интерполирует назначенные номера — неправильный
порядок он не обнаруживает. Заполнение полюсов и экстраполяция не являются
измеренными значениями; им нужна отдельная маска происхождения/достоверности.

### S4: фаза, OPD и поверхность

`orders*λ` верно для OPD. `orders*λ/2` верно для высоты отражающей поверхности
при принятой нормальной геометрии и направлении чувствительности.
Это **две разные величины**, хотя сейчас они лежат в `wavefrontMap()` и
переключаются одним флагом doublePass. Для наклонного падения и сложной схемы
нужна модель чувствительности, а не безусловный множитель 1/2.

Карта остатка после удаления полиномов тоже не автоматически является картой
съёма для CAM: часть аберраций может быть реальным дефектом детали, который
нельзя исключать только потому, что он хорошо подгоняется полиномом.

### Модальный анализ и отчёт

- Совместный МНК использует pivoted QR, проверяет ранг и конечность решения.
  Низшие ненормированные полиномы Цернике алгебраически соответствуют принятому
  соглашению Y вверх. RMS-нормировка коэффициентов выполняет обратное деление
  на нормировочный множитель, что математически верно.
- Цернике ортогональны на полном единичном диске. На маске другой формы
  коэффициенты можно подгонять совместно, но они коррелируют; правило «RMS
  равен норме коэффициентов» без поправок применять нельзя.
- Gram–Schmidt ортогонализует **всю** иерархию, затем выбирает включённые члены.
  При неполном выборе термов это другая задача, чем МНК исходных выбранных
  полиномов. UI/документация должны различать эти два смысла чекбоксов; равенство
  остатков всех режимов при произвольном выборе не гарантировано.
- Центр и радиус нормировки выводятся из bounding box валидных точек.
  Изменение маски качества может менять базис и коэффициенты одной детали.
  Физическая нормировочная апертура должна задаваться независимо от пропусков.
- Серегинские множители ×2 для комы/сферической и особенно трилистника в отчёте
  прямо обозначены в коде как эмпирические. Их нельзя считать независимой
  валидацией по одному файлу. Требуются чистые моды разных амплитуд и углов.
- Последовательная схема — режим совместимости. Подтверждены не все её
  коэффициенты и правила отображения; не следует заменять ею основной МНК
  только из-за визуального совпадения одного отчёта.
- RMS before считается на эродированной выборке, PV before — на полной карте.
  Это разные области оценки, что нужно показывать или унифицировать.
- Поправка doublePass в оценке Strehl уже реализована правильно. Оценка Марешаля
  остаётся приближением, не рассчитанной PSF, особенно вне режима малых ошибок.

## 5. Реальные данные и эталон Digit

`big.idf`, режим `--no-refine`, стандартная круглая апертура: расхождение половин
54,77°, остаток модели 4,65 уровня при амплитуде 28,62, две области развёртки,
17 897 точек исключены по модуляции и 1342 как мелкие острова. Несмотря на это
CLI завершился кодом 0. Эти значения не доказывают конкретную ошибку фазы без
эталона, но демонстрируют необходимость отдельного QC-статуса результата.
Подбором апертуры можно изменить числа; использована стандартная, не ручная.

`Terminal.bmp`, без продления полос, со стандартной апертурой, после обхода
проблемы размещения CLI: трассировка/экспорт успешны. В `mtr_diff` для карты
разности, сведённой инструментом на 201×201, RMS before = **13,49 нм**, после
его модального разложения = **9,47 нм**, при λ=632,8 нм и doublePass=OFF.
Сетки/нормировочные апертуры двух файлов отличаются. Это контрольная точка,
а не доказательство точности 9,47 нм и не установленный допуск приёмки.
Удаление мод может скрывать систематическую ошибку, поэтому сохранять нужно
и исходную разность, и список удалённых мод.

Существующие E2E-тесты полезны для регрессий, но допускают для дефокуса и
сферической до `max(60%,100 нм)`. Их прохождение не является метрологической
приёмкой стенда. Новые AlgorithmRegressionTest существенно строже в своей
ограниченной области применимости.

## 6. Что взять из Notes

**Принять:** раздельные Grid/Frame/Transform/Resampler; разделение G1/G2/G3/G4;
хранение КПФ в стабильной приборной СК; независимость юстировки и дефекта детали;
общий выход восстановления фазы; отчёт потерь при обмене; immutable входы,
версии алгоритмов и происхождение результата.

**Уточнить до реализации:** физическую величину и знак каждой карты, оптическую
чувствительность, область применимости КПФ, интерполяцию масок, единицы реперов,
привязку к CAM и разрешённые вычитаемые моды. Само наличие одинакового TS/TF
не доказывает переносимость одной КПФ между схемами: нужна проверка неизменности
систематики и соответствия точек зрачка.

**Не делать обязательным для v1:** универсальный визуальный DAG, произвольные
UI-плагины, GPU/streaming, все внешние форматы, все дифракционные анализы.
Доращивать текущую архитектуру под проверенный рабочий сценарий дешевле и
проверяемее. Замечание коллеги из `addition-info.txt` приоритетно: для цеха
сначала хороший Fourier, апертуры и дисторсия, затем сложный редактор полос.

## 7. Воспроизведение

PowerShell из корня проекта, установленный MSYS2 MINGW64:

```powershell
$env:PATH = 'C:\msys64\mingw64\bin;' + $env:PATH
cmake --build build -j 1
$env:QT_QPA_PLATFORM = 'offscreen'
ctest --test-dir build --output-on-failure
python notes/audit/phase_plugin_probe.py --output build/phase-plugin-probe.json
g++ -std=c++17 -Isrc notes/audit/core_probe.cpp build/src/core/libcore.a build/src/aperture/libaperture.a -LC:/msys64/mingw64/lib -lopencv_core -o build/core-audit-probe.exe
./build/core-audit-probe.exe
./build/tools/psi_check/psi_check.exe notes/IDF/big_4.idf
./build/tools/psi_check/psi_check.exe notes/IDF/big.idf --no-refine
```

Для `terminal_pipeline` до исправления A07:

```powershell
Copy-Item build/tools/terminal_pipeline/terminal_pipeline.exe build/src/audit-terminal-pipeline.exe
./build/src/audit-terminal-pipeline.exe test_data/Terminal.bmp build/audit-terminal.mtr
./build/tools/mtr_diff/mtr_diff.exe test_data/Terminal_digit.mtr build/audit-terminal.mtr
```

Сохранены [результаты DLL](audit/phase-plugin-results.json) и
[результаты core](audit/core-probe-results.txt).
Диагностические пробы намеренно не являются зелёными приёмочными тестами:
они печатают поведение, включая обнаруженные дефекты. После исправлений
критические случаи следует перенести в CTest с явными допусками.

Первоисточники для проверки принципов:

- [Takeda, Ina, Kobayashi, 1982](https://doi.org/10.1364/JOSA.72.000156):
  спектральное выделение фазы одиночной интерферограммы с несущей.
- [Liu et al., 2013](https://doi.org/10.1364/OE.21.029505):
  трёхшаговое уточнение фазовых сдвигов с наклонами; PDF есть локально.
- Парпин, Серегин, 2012: локальный PDF в `notes/Phase-shift/`, формулы (6)–(16).
- [Zernike Polynomials: Evaluation, Quadrature, and Interpolation](https://arxiv.org/abs/1811.02720):
  область ортогональности и работа с базисом на диске.

Выводы о конкретных дефектах основаны на коде и исполненных пробах;
ссылки на статьи подтверждают методы, но не верифицируют нашу реализацию.
